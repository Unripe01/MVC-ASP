# 特定帳票 帳票システム再設計アウトライン（叩き台）

## 0. 前提・目的

### 現状課題

* 帳票定義がDB・JS・Controller・case文へ分散
* 帳票項目とマスター項目の依存追跡不可
* SpreadRow index依存
* 帳票ごとの特殊処理分散
* 入力UIが業務OS化
* 「帳票追加」「項目追加」が高コスト
* 属人化（暗黙DSL化）

### 新システムで守りたいこと

* CRUD主体の純粋ドメイン設計
* 帳票を後付け可能にする
* 帳票定義をコードとして管理
* IDE追跡可能
* 定義追加中心の開発体験
* XMLスナップショット保存
* マスター取得／逆反映を定義ベース化
* Wordテンプレート活用

---

# 1. システム全体責務分離

## 1-1. CRUD領域

責務：

* マスター管理
* 通常編集
* 一覧
* 検索
* 業務データ管理

構成：

```text
Controller
 ↓
ApplicationService
 ↓
Repository
 ↓
Entity
```

補助：

```text
ViewModel
```

---

## 1-2. 帳票領域

責務：

* 帳票定義
* 帳票入力
* 帳票保存
* 帳票出力
* マスター連携

構成：

```text
ReportDefinition
 ↓
ReportEngine
 ↓
Renderer / Serializer / UI
```

---

# 2. 帳票定義思想

## 2-1. 帳票 = コード定義

例：

```csharp
public class D3_GaikokujinList : ReportDefinition
{
    protected override void Configure()
    {
        Field(x => x.Name);

        Field(x => x.Company.Name);

        Field(x => x.Favorites)
            .AsMultiSelect();
    }
}
```

目的：

* IDE追跡可能
* Rename安全
* 使用箇所検索可能
* 型安全

---

## 2-2. 帳票定義が持つ責務

帳票定義から生成可能にしたいもの：

* 入力UI
* Word差し込み
* XML serialize
* XML deserialize
* マスター取得
* マスター逆反映
* 編集ダイアログ起動
* バリデーション
* 使用項目解析

---

# 7. 保存戦略

## 7-1. 帳票スナップショット保存

```text
ReportInstance
 - WorkerId
 - ReportId
 - XmlData
```

目的：

* 帳票専用テーブル増殖防止
* 制度変更耐性
* 柔軟な帳票追加

---

## 7-2. XML採用理由

* C#クラスとの相性
* Serialize容易
* Snapshot保存向き
* Word差し込み親和性
